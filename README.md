# Автопідбір

Вебзастосунок для пошуку та підбору автомобільних запасних частин.

## Запуск

```
npm install
npm start
```

Застосунок відкривається на http://localhost:3000/

## Збірка

```
npm run build
```

## Маршрутизація

Використано `react-router` 7.18.4 (декларативний режим, один `BrowserRouter` у `src/index.js`).

Адреси для перевірки:

- `/parts?q=колодки&available=1`
- `/parts/p-001`
- `/searches/new?partId=p-001`
- `/searches/s-001/edit`

Для хостингу потрібно повертати `index.html` для клієнтських маршрутів (SPA fallback). Незбережені чернетки скидаються при виході зі сторінки, зміні запису та перезавантаженні.

## Джерело даних (Л 3.2)

Доступ до підборів відокремлено від компонентів сервісним контрактом `searchService` (`getAll`, `getById`, `create`, `update`, `delete`). Реалізація вибирається в одному місці — `src/services/searchService.js` — за змінною середовища.

| Змінна | Значення | Призначення |
|---|---|---|
| `REACT_APP_DATA_SOURCE` | `mock` (типово) або `api` | Вибір реалізації сервісу |
| `REACT_APP_API_BASE_URL` | напр. `http://localhost:3000/api` | Базова адреса REST API (лише для `api`) |

Шаблон змінних — `.env.example`. Для власних значень створіть `.env.local` (виключений з Git). Після зміни змінних перезапустіть `npm start` або повторіть `npm run build`. У змінні `REACT_APP_` не записуйте секрети: вони потрапляють у клієнтську збірку.

**Режим mock** (типовий, працює без сервера): дані зберігаються в `localStorage` цього браузера під ключем `autopidbir.searches.v1`, мають затримку 600 мс і дозволяють відтворити одноразову відмову. Початкові записи з `src/data/searches.js` використовуються лише коли ключ відсутній; збережений порожній список не замінюється початковими даними. Сховище прив'язане до origin (схема, хост, порт).

**Режим api**: адаптер `src/services/apiSearchService.js` очікує `GET/POST /searches`, `GET/PUT/DELETE /searches/:id` (200, 201, 200, 204; відсутній запис — 404). Адаптер перевірено лише локальною тестовою заглушкою; фактичний зовнішній сервіс не підключено.

Перевірка відмов у режимі розробки (`npm start`, режим mock): у розділі «Підбори» є блок «Навчальна перевірка відмов». У виробничу збірку він не потрапляє.

Обмеження: зміни з іншої вкладки не надходять автоматично (є кнопка «Оновити дані»); транзакцій між вкладками немає; перемикання режиму не переносить локальні записи на сервер.

Правила полів підбору: `src/domain/searchValidation.js`.
