# Сценарій захисту «Автопідбір»

Режим: production-збірка (`npm run build`, `npx serve -s build`), джерело даних — mock (`localStorage`). Реальний зовнішній API не підключено.

## Перевірочні дані

Початково є два підбори: `s-001` (Гальмівні колодки передні, Volkswagen Golf VII, 2 шт., термінова) і `s-002` (Масляний фільтр, Toyota Corolla E210, 1 шт.). Створені під час показу записи видаляються в кінці. Відновлення лише цієї колекції: у DevTools видалити ключ `autopidbir.searches.v1` (не `localStorage.clear()`).

## Послідовність (5–7 хвилин)

1. Потреба: водій вибирає запчастину й залишає запит на підбір для свого авто.
2. Каталог: пошук і фільтр «Лише в наявності» (параметри в URL), відкрити деталі запчастини, «Вибрати й підготувати підбір».
3. Некоректна спроба: порожня форма, потім кількість `1e1` — повідомлення біля полів, фокус на першому. Виправити й створити.
4. Підтверджені деталі за адресою `/searches/:id` з повідомленням про успіх; «Редагувати підбір», змінити кількість, зберегти — той самий id.
5. Список: пошук, «Термінова», сортування; порожній результат й повернення до всіх.
6. Видалення: скасувати діалог (запис лишається), потім підтвердити для перевірочного запису.
7. Перезавантажити сторінку з прямою адресою підбору — запис на місці (localStorage).
8. Межа сервісу: показати `npm run test:run`, тест відмови створення (введення не втрачається) і `src/services/searchService.js` — єдине місце вибору джерела.
9. Відомі обмеження: зміни з іншої вкладки не надходять автоматично; API адаптер перевірено лише тестами із підміненим fetch і локальною заглушкою; для хостингу потрібне правило повернення `index.html`.

## Запитання, до яких слід бути готовим

Змінити затримку (`mockDelayMs` у `mockSearchService.js`), відтворити відмову (у `npm start` блок «Навчальна перевірка відмов»), пояснити захист повторного подання (`submitting` ref + `isSubmitting`), знайти пропущений `await`, показати місце заміни джерела.
